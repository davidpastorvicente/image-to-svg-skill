# Layout: consistency, alignment and centring

A reference raster (especially AI-generated or hand-made artwork) is full of
small layout inconsistencies: "identical" shapes with slightly different
sizes, headings of the same role at different font sizes, paired rules of
different lengths, a text column whose lines start at slightly different x.
Measuring each object on its own faithfully copies all of them. Users notice
("are these the same size? are these aligned?"). Treat the layout as a **system**, not as a list of
measured objects.

## 1. Find the equivalence classes (during analysis)
List objects that play the same role and must therefore be identical:
- repeated decorative shapes: backdrop shapes, bars, icons, badges, frames;
- text roles: titles, subtitles, captions, labels, footers — each role
  has ONE font, size, weight, letter-spacing and colour;
- rules: section dividers (same width), paired rules (equal and mirrored);
- repeated blocks: e.g. heading → rule → two lines of text in every section,
  with the same vertical rhythm;
- colour pairs: the relation between paired colours (light vs dark tint) is
  the same in every section (see typography-and-colour.md).
Propose these classes to the user together with the object structure, and
ask about the ones where the difference might be intentional (e.g. a smaller
shape behind a smaller illustration). Default: unify.

## 2. Define the grid
- **Margins**: one left and one right margin, symmetric about the page centre
  (`left = W - right`). Text columns, bars, dividers and the outer ends of
  illustrations' ground lines all start/end on them. Derive the margins from
  the reference (median of the aligned edges) and round sensibly.
- **Page centre**: centred items (tagline, footer) are centred exactly on
  `W/2` by their ink; paired items (left/right rules) are mirrored about it.
- **Vertical rhythm**: for repeated blocks, fix the gaps (baseline → bar,
  bar height, bar → first line, line spacing) as constants = mean of the
  reference values, and anchor each block at one measured point (e.g. its
  title baseline).
- **Shared "roof" between text and illustration**: inside a section, the
  title block starts level with a key feature of its illustration (e.g. the
  top of the backdrop circle). Align the capitals' top line — baseline −
  capHeight·size/UPEM (OS/2 `sCapHeight`) — not the ink top, so accents
  and round overshoots (O, S) don't shift it. Derive the title
  baseline from the feature in code, and apply the same rule in every
  section; move the whole text block so its internal rhythm is kept.
- **Section spacing**: the empty gap between consecutive sections (bottom of
  one section's ink → top of the next, backdrop shapes included) is the same
  everywhere — use the mean of the reference gaps and move the middle
  sections. Each divider sits exactly midway in its gap. A divider measured
  from the reference is usually off-centre (e.g. 38 above / 79 below).
- Moving an illustration so its ground line meets the margin is fine; move
  the whole illustration group (backdrop and its clip path included).

## 3. Encode it as constants
Put the system at the top of the build script:
```python
PAGE_W = 1000
FRAME = (80, PAGE_W - 80)    # left/right margin, symmetric about the centre
SHAPE_R = 140                # every backdrop shape of one class
HEADING_SIZE, BODY_SIZE = 60, 26
BAR_W, BAR_H = 60, 8
HEADING_TO_BAR, BAR_TO_TEXT, LINE = 40, 50, 38
RULE_W = 100
```
Each section is generated by the same function with only its content and
alignment (left/right) as parameters. Then equality is guaranteed by
construction, not by careful measurement.

## 4. Align text by its real ink
Font metrics alone don't tell where the ink lands (side bearings, kerning,
the renderer's shaping). Let Inkscape measure it:
1. Build the SVG with each text at `x=0`.
2. `inkscape file.svg --query-all` → visual bbox of every object (in px of
   the page width; multiply by `viewBox_width / width_px`).
3. Set `x += anchor - ink_edge` (left: x0; right: x1; centre: (x0+x1)/2).
Translating a text doesn't change its width, so one query is enough.

## 5. Shared letter-spacing per text role
Prefer one `x` + `letter-spacing` per text over per-glyph `x` lists: it stays
editable (retyping keeps the spacing) and guarantees equal spacing across a
role. Calibrate it from the reference: ink width is linear in letter-spacing,
`W(t) = W(0) + t·(n − 1)` (n = characters incl. spaces). Render once with
`t = 0`, query widths, solve `t` for each reference line of the role, average.

## 6. Centre the whole artwork
After everything is placed, query the union bbox of all layers and translate
everything by `(W/2 − cx, H/2 − cy)`. **Bake** the translation into the
coordinates (path data, cx/cy, x/y, clip paths in `<defs>`) instead of adding
`transform` attributes, so objects keep clean absolute coordinates in
Inkscape (`svgkit.translate_path`). If you translate, keep reference
comparisons working by storing the offsets (e.g. `checks/layout.json`) and
shifting the render crop back when comparing.

## 7. Geometric vs optical alignment
Letters like J, A, T, V, slashed or accented capitals, or round O/C overshoot or have overhangs. Optical
alignment (aligning a stem, not a stroke or overhang) is typographically nicer but
makes the measurable bbox asymmetric, so the "artwork centred" and "margins
symmetric" checks can't both hold. Default to ink (geometric) alignment, which
users can verify in Inkscape; mention the optical option.

## 8. Show spacing questions visually
When a spacing decision is open (e.g. the footer sits closer to the last
section than sections to each other), render current vs proposal side by
side with coloured bands and the measured gaps, instead of describing it.
Many such differences are intentional (a footer is a different role); offer,
don't impose.

## 9. Verify
Run `scripts/consistency.py file.svg`. It flags near-equal circles, rects and
rules that differ; texts with the same role (same `inkscape:label`) or similar
size that differ in size/spacing/family/weight/fill; per-glyph x lists;
almost-aligned left/right edges; asymmetric margins; unequal or unmirrored
rule pairs; different vertical rhythm between layers with the same structure;
and an off-centre artwork bbox. Also add project-specific asserts to the
project's validate script (radii equal, margins equal, bbox centred), so
later edits can't silently break the system.
